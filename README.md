# Engineering Research

**AIの開発リサーチで、信頼性の低い情報源を根拠から外し、実装に使える技術情報を調査・検証するスキル。**

## 課題

AIにAPI調査やライブラリ比較、バグ調査を任せると、検索で見つかった記事が、そのまま実装の根拠になることがあります。

でも、説明がもっともらしいことと、技術的な裏付けがあることは別です。

- **実際に検証していない記事が混ざる。** まとめ記事や量産SEO記事には、他の情報を言い換えただけで、実装・測定・再現の裏付けがないものがあります。
- **同じ情報の繰り返しが、複数の根拠に見える。** 5つの記事が同じ資料を参照していても、独立した証拠が5つあるわけではありません。
- **正しい情報でも、今のプロジェクトには使えない。** 古いAPI、別のOS、異なるランタイムの回避策を、そのまま適用できるとは限りません。
- **確認できた事実と、推測が混ざる。** 出典が付いていても、その資料が結論を裏付けているかは別途確認が必要です。

こうした情報を根拠に進めると、使えないAPIや条件の合わない回避策を採用し、実装の手戻りにつながります。

## このスキルが解決すること

Engineering Researchは、AIが調査結果を実装の根拠にする前に、**「その主張を何で確かめられるか」「今の環境に適用できるか」**を検証するための指示を与えます。

| 課題 | このスキルで行うこと |
|---|---|
| 裏付けのない記事を採用してしまう | 公式Docs・仕様・実装・テストまで根拠をたどる。裏付けのない記事は、情報を探す手掛かりにとどめる |
| 転載や言い換えを複数の証拠として数える | 元の出典を確認し、独立した証拠があるかを判断する |
| 古い情報や別環境の解決策を使う | プロジェクトのバージョン・OS・ランタイムと、情報の適用条件を照合する |
| 有力そうな結論をそのまま信じる | 制約、非対応環境、既知の不具合、非推奨化など、結論が成立しない条件も探す |
| 事実と推測が混ざる | 仕様に書かれた事実、再現できた挙動、推論、未検証の仮説を分けて報告する |

開発者が、**何を根拠に、どの条件で実装に使えるのか**を判断できる調査結果を目指します。

個人ブログやStack Overflowも、具体的な再現手順や測定結果があれば有用です。情報源の種類だけで一律に排除せず、主張を支える証拠と適用条件で判断します。

調査量も問いに合わせます。公式Docsの確認で解決する問いはそこで終え、追加調査で判断が変わり得る場合に深掘りします。

## 使う場面

| 調査 | 確認すること |
|---|---|
| API・SDKの使い方 | 対象バージョンの仕様と、サポートされる使い方 |
| ライブラリ選定・移行 | 互換性、制約、変更履歴、既知の問題 |
| バグ・OS固有の挙動 | 再現条件、関連コード、修正状況 |
| 性能比較 | 測定条件、ワークロード、環境、再現可能性 |
| セキュリティ | 影響を受けるバージョン、修正、技術的根拠 |

Web、デスクトップ、モバイル、バックエンドの開発が対象です。市場分析、価格戦略、マーケティングなどのビジネス調査は対象に含めません。

## インストール

[skills CLI](https://github.com/vercel-labs/skills)で、使用するエージェントを選んで導入できます。

```bash
npx skills add tanakaisworking/engineering-research --skill engineering-research
```

CodexまたはClaude Codeのプロジェクトへ導入する例です。

```bash
npx skills add tanakaisworking/engineering-research --skill engineering-research --agent codex
npx skills add tanakaisworking/engineering-research --skill engineering-research --agent claude-code
```

## 使い方

**導入後は、普段どおりAIに開発や技術調査を依頼してください。毎回 `$engineering-research` を指定する必要はありません。**

スキルの自動選択に対応したエージェントでは、依頼内容に応じてAIがこのスキルを選んで使います。作者の利用環境でも、スキル名を指定せずに技術調査で使われることが多くあります。これは実際の使用感で、自動利用の頻度はエージェント・設定・依頼内容によって変わります。

### 明示的に使いたい場合（任意）

このスキルを使うよう指定したいときは、次のようにスキル名を添えて依頼できます。以下は任意の呼び出し例です。

```text
$engineering-research
このプロジェクトで使っているSDKのバージョンを確認して、
このAPIの正式な使い方と対応するランタイムを調べて。
```

```text
$engineering-research
このエラーに関するIssueと修正履歴を調べて。
回避策が今のOS・ライブラリのバージョンに適用できるか確認して。
```

```text
$engineering-research
この2つのライブラリを、今回の用途と実行環境に合わせて比較して。
比較記事の結論だけでなく、仕様・実装・測定条件まで確認して。
```

## 内容

- [SKILL.md](SKILL.md)：技術調査の範囲、証拠の評価、検証、報告の指示。
- [agents/openai.yaml](agents/openai.yaml)：Codex向けの表示名と呼び出し例。

検索・ブラウザ・コード実行には、利用するエージェントが提供するツールを使います。このリポジトリは調査方針を定めるスキルで、検索サービスそのものは含みません。
